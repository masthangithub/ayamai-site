Can a machine keep learning, and keep returning to what it has learned?

DREAMS (Data Relations, Entropy, And Mind Simulations) is an AYAMAI project about continual learning, memory and reflective loops in AI systems. We are sharing early sketches and open questions to find people who want to explore them with us. It is not a product, and it makes no claims about machine awareness.

DREAMS project · Started 2025 · Early symbolic prototypes in Python · Open to collaborators

The working hypothesis in one picture. An experience is encoded as data, linked into memory, recombined during a “dream” pass, and narrated back as a revised understanding. Affect-like signals set how far each pass wanders. Each station names the folder where its sketch lives.

The DREAMS idea, in three parts

These are framings we find useful for asking questions. They are analogies, not descriptions of how the brain works.

The model as substrate

We treat a language model as a store of data, the relations between data, and patterns of how information flows. It is where knowledge sits, not the whole of a system.

Workflows as thinking

An agentic workflow, with tools, resources, prompts and a logical order of steps, is one act of “thinking”. Each such workflow is its own small AI application.

Learning without forgetting

When results of new tasks feed back as training data, models tend to lose older skills. We want to study established remedies here: replay, parameter regularisation, growing architectures and meta-learning.

Three DREAMS working terms

Our own vocabulary, kept deliberately simple until each can be given a precise data type.

U

Understanding: a perception or insight, before it is written down.

D

Data: a symbolic description of U that a system can store, link and recombine.

UI

Understanding Intelligence: the loop U → D → new U, repeated over time.

DREAMS research questions

Each of these connects to an existing line of research. We list the connections so that the questions can be tested rather than argued.

Can “dreams” act as replay?

If a system generates recombinations of past experience, can that output be used to reduce forgetting? This is close to generative replay.

What is a unit of understanding?

What data structure should U become: an embedding, a graph node, a short text, or a mix? Today it is a placeholder.

Is affect a useful control signal?

Could signals like curiosity or uncertainty decide what to recall and how far to explore? This overlaps with work on intrinsic motivation.

How should memory change?

When should a memory graph consolidate, prune or re-link? Complementary learning systems theory offers one starting model.

How would we know it helped?

Every loop needs a measure. For forgetting, the standard ones are backward and forward transfer on a sequence of tasks.

What can older traditions offer?

Ideas from Ayurveda and Kashmir Shaivism shaped some sketches. We treat them as sources of metaphor and questions, not as evidence.

A DREAMS loop sketched in mid-2025

The dream_loop/dreamlike_3 scripts chain a language model, a relevance filter and web retrieval into a goal-directed cycle that feeds its own output back in. This was written by hand, before agent frameworks made such loops routine.

  1. Goal and seedA goal and an input description start the cycle.
  2. DraftAn LLM writes ten candidate lines toward the goal.
  3. SelectTF-IDF similarity keeps the lines closest to the goal.
  4. RetrieveWeb pages about the goal add context terms.
  5. RemixAn entropy linker recombines tags into the next input.

↺ The remixed text becomes the next seed, for a set number of iterations.

The same pattern is now common under names such as reflection, iterative retrieval and self-refinement. We share this early version as a starting point to rebuild with current tools, not as a claim of priority.

Next steps for DREAMS

Models, agent frameworks and fine-tuning methods have moved quickly since these sketches. The next phase is to make each idea measurable.

Directions, not commitments. The order may change with what collaborators bring.

  1. Give U and D precise types

    Replace the placeholder encoder with a defined structure, likely a graph node holding an embedding, a short text and typed relations.

  2. Rebuild the loops on an agent framework

    Move the dream and narration loops onto a graph-based orchestration library with persistent memory, so every step is inspectable.

  3. Test dreaming as generative replay

    Fine-tune small open models with adapters on a sequence of tasks, and compare no replay, real replay and generated replay on measured forgetting.

  4. Turn affect into measured signals

    Swap hand-set emotion vectors for quantities a system can compute, such as prediction error or uncertainty, and test whether they improve recall.

  5. Publish what we find

    Share code, data and results openly, including results that do not support the idea.

Related work we are reading

A starting list, not a claim of building on all of it.

  • McClelland, McNaughton and O’Reilly (1995). Complementary learning systems.
  • Kirkpatrick et al. (2017). Elastic weight consolidation.
  • Shin et al. (2017). Continual learning with deep generative replay.
  • Rusu et al. (2016). Progressive neural networks.
  • Finn, Abbeel and Levine (2017). Model-agnostic meta-learning.
  • Pathak et al. (2017). Curiosity-driven exploration by self-supervised prediction.
  • Shinn et al. (2023). Reflexion: language agents with verbal reinforcement learning.
  • Madaan et al. (2023). Self-Refine: iterative refinement with self-feedback.
